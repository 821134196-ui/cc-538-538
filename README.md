# 绿园 · 公园树木认养系统

本地单机的公园树木认养演示应用：树木地图、认养申请（期限互斥 + 占位释放）、
养护日历、巡查照片（亮度校验）、异常两级复核与年度反馈。纯 Python 标准库后端 +
原生前端（SVG 地图），SQLite 存计划，照片存本地，支付/短信用模拟适配器。

## 一条命令启动

```bash
./run.sh            # 首次自动初始化 SQLite 并预置演示数据（含 T004 移栽案例）
# 重置演示数据：
./run.sh --reset
# 自定义端口：
PORT=8080 ./run.sh
```

打开 http://127.0.0.1:8000/ ，右上角切换演示身份：

| 身份 | 账号 | 能做什么 |
|---|---|---|
| 李阿姨 / 王居民 / 周同学 | 1 / 2 / 3 | 申请认养、支付、执行浇水任务、上报异常、看年度反馈 |
| 陈园艺 | 10 | 制定计划、核实居民上报（误报归档 / 提交诊断）、登记移栽、解封 |
| 赵主管 | 20 | 复核园艺师诊断，批准后健康结论才生效 |

- **T002**：王居民有一个 10 分钟后到期的**未支付占位**（可观察自动释放）。

## 核心业务规则

- **期限互斥**：同一树的 `pending/active` 认养单区间不得重叠；申请在
  `BEGIN IMMEDIATE` 事务中先清扫过期占位再判定，并发申请按提交时间先到先得。
- **占位释放**：申请后锁定名额 30 分钟（`HOLD_MINUTES`），未支付到期由后台
  每 30 秒（及启动时）清扫为 `expired`，名额立即重新开放；逾期后支付被拒。
- **计划随事件更新**：支付生成浇水(每 14 天)/修剪(春秋)/病虫观察(每月)计划；
  移栽 → 复壮期取消近期任务并加密观察；封控 → 冻结全部待办；解封/批准诊断 →
  从当天起恢复计划；认养人退出 → 终止待办并模拟退款；逾期 → 任务转 `overdue`
  并短信提醒，可补做留痕；误报 → 归档并安排 7 天后复查。
- **健康结论两级制**：居民上报不改变健康状态；园艺师只能提交诊断；主管批准后
  才写入 `trees.health_status` 并联动封控/解封。认养人无权修改专业结论。
- **认养状态与健康状态分开展示**：详情页两个独立状态卡；地图圆点填充色＝健康，
  外圈＝认养（绿圈认养中 / 粉圈我的 / 琥珀虚线占位 / 红圈封控）。
- **跨用户隐私**：居民只能看自己的认养单/年度报告/日历；他人认养在树木详情中
  脱敏（不显示认养人、支付信息）；照片上传者、事件操作人对非员工匿名。
- **照片亮度**：前端 canvas 预检 + 服务端独立解析 PNG 复测，平均感知亮度
  < 0.42 拒绝归档（前端提供"一键补光后重检"演示）。

## 测试

```bash
python3 -m unittest tests.test_all -v
```

覆盖：期限互斥（含 8 线程并发抢同一档期，恰好一单成功）、占位到期释放与过期
支付拒绝、异常误报/驳回/批准两级流程、跨用户服务层与 HTTP 403 隐私、预置移栽
案例计划重算、逾期清扫与补做、认养退出退款、照片亮度门槛。

## 目录结构

```
db.py         SQLite schema 与连接（WAL + 外键）
services.py   全部业务规则（事务、互斥、计划重算、复核、年度报告、脱敏序列化）
adapters.py   模拟支付网关 / 模拟短信通知
imaging.py    纯标准库 PNG 生成（巡查照片）与亮度计算
seed.py       预置演示数据（python3 seed.py --reset）
server.py     http.server JSON API + 静态文件 + 后台清扫线程
main.py      启动入口（初始化→预置→清扫→启动）
web/          index.html / style.css / app.js（无框架，SVG 地图）
tests/        test_all.py（27 个用例）
data/         运行时生成：trees.db、photos/*.png（已 gitignore）
```
